# 待测试

- 图片节点的 Codex ImageGen 生成与迭代每次使用独立新 thread，不复用或覆盖助手普通对话的 thread；连续生成至少 4 次（含带参考图迭代）时确认每次走 `thread/start`，图片回填与来源连线正常，之后普通聊天仍恢复原 thread。此调整避免跨轮图片历史累积，本轮附件或单轮多张生成仍可能触及上游请求体限制；助手聊天中临时要求生图不属于此隔离入口。
- 图片节点选择“Codex ImageGen”：不会创建新画布或重复的空生图节点；空图片节点无参考图时按提示词从零生成并填入该节点；已有图片时以原图迭代并新建连接结果，保留原图。
- 图片节点模型列表选择“Codex ImageGen”后，主生成按钮按当前提示词直接生图；“AI 优化”改为独立按钮，只返回文本优化稿，弹窗可查看原文并编辑优化稿，选择“采用并生成”“使用原文生成”或取消。确认优化期间不产生图片、不修改节点内容；取消保留原文，空优化稿不能采用，失败或停止不会自动生图，生成结果保留实际采用的提示词。窄面板中模型、设置和生成控件应换行而不重叠。
- Codex ImageGen 生成期间空图片节点显示“Codex 正在生成”；迭代时保留原图并显示“Codex 正在生成新版本”；成功或失败后状态应清除。失败提示显示可用的具体类型、额度耗尽重置时间，以及 Codex 返回的说明。
- Codex ImageGen 设置面板可配置画幅/尺寸、质量和张数；生成请求会自动带入对应要求，多张时要求逐次调用 ImageGen，迭代结果节点应保留本次设置。验证设置切换会写入节点配置，生成时正确引用；精确像素、质量和张数受 ImageGen 工具限制，可能无法严格保证。
- Codex 参考图在发送前按整轮 3 MiB 图片数据预算压缩，无法读入或压缩到预算内的图片会省略并告知模型；浏览器控制台分别记录画布发往本地 Agent 的 `thread/start`、`thread/resume`、`turn/start` 请求 UTF-8 字节数和图片数据量，不输出提示词或图片内容。复现 413 时核对 F12 中 `[Codex RPC 请求体积]` 的方法、字节数和图片数。
- 收起画布 Agent 侧栏不会中止正在运行的任务；重新展开后任务与状态仍保留。显式停止按钮仍应正常中止任务。
- Fork 的 Docker 发布：合并到 `main` 后确认 GitHub Actions 构建多架构镜像并推送 `ghcr.io/tyreamon/infinite-canvas:latest`；VPS 更新后验证拉取和启动。
